# Rucene 0.1.0 Release Notes

**Version:** 0.1.0
**Date:** 2026-11-21
**Code commit:** `83d13c9` (`develop`); the `release/0.1.0` branch adds documentation and `NOTICE` only
**Target:** Apache Lucene Core 10.5.0

## Overview

Rucene 0.1.0 is the first release of Rucene, a Rust port of Apache Lucene
10.5.0 that aims at functional parity and index-file compatibility with it.

This release contains:

* `rucene`, the port of `lucene/core`;
* the ports of `lucene/codecs`, `lucene/analysis/common`, `lucene/queries`,
  `lucene/queryparser`, and `FuzzyLikeThisQuery` from `lucene/sandbox`;
* the ports of `lucene/test-framework` and of the randomizedtesting 2.8.1
  runner, on which Lucene's own tests run in Rust;
* two command-line examples, `rucene-cli` and `rucene-base`.

The knowledge graph reports every in-scope module as `fullyPorted`, with 0 absent
members. This is a structural measure: it counts the Lucene types and members
that have a Rust counterpart. The behavioural evidence is the test suite and the
Java-oracle tests described below. The full, sourced list of what is ported and
what is not is in [`CHANGELOG.md`](../../CHANGELOG.md#010---2026-11-21).

## Highlights

* **Bidirectional index compatibility with Lucene 10.5.0** for the default
  `Lucene104` codec: Lucene opens and checks indexes Rucene writes, and Rucene
  opens and checks indexes Lucene writes
  (`tests/portability/index_interop.rs`).
* **Byte-identical files** for stored fields, term vectors, norms, doc values,
  points, kNN vectors, postings, and segment metadata
  (`tests/portability/`).
* **Lucene's test suites, ported**: 5330 tests, all passing on this tree.

## Compatibility

* **Lucene:** Apache Lucene Core 10.5.0 only. Rucene reads and writes the
  formats of Lucene 10.5.0's `lucene/core` and `lucene/codecs`. It does not read
  older formats that need `lucene/backward-codecs`.
* **Rust:** every crate declares `rust-version = "1.89"` and `edition = "2021"`.
  This release was built and tested with Rust **1.99.1**; a build with 1.89 was
  not run for this release.
* **Platform of the release evidence:** Linux 7.0.0, x86_64.
* **Features:** `default = ["std", "mmap"]`. The `zlib-c` feature links the C
  zlib, which makes `BEST_COMPRESSION` stored fields byte-identical to Lucene's;
  it needs a C compiler.

## Build and test

```bash
cargo build --release              # the rucene crate
cargo test --workspace             # every workspace crate
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

`cargo build` and `cargo test` without `--workspace` cover only the `rucene`
package, because the workspace declares no `default-members`.

Many tests compare Rucene with Lucene 10.5.0 by running Java. They fail, rather
than skip, when a requirement is missing:

* a JDK on `PATH` (Java 21 or later for Lucene 10.5.0; JDK 25 for the
  `rucene-analysis-common` JDK oracles);
* Maven on `PATH`, for the harness in `tests/fixtures/java-codec-harness/`;
* the Lucene 10.5.0 jars (`lucene-core`, `lucene-codecs`,
  `lucene-analysis-common`, `lucene-test-framework`) and
  `randomizedtesting-runner` 2.8.1, `junit` 4.13.1 and `hamcrest` 2.2 in the
  local Maven repository (`$HOME/.m2/repository`).

See [`README.md`](../../README.md) for the details.

## Known limitations

The complete, sourced list is in
[`CHANGELOG.md`, Known limitations](../../CHANGELOG.md#known-limitations). In
short:

* **28 Lucene modules are not ported**, among them `facet`, `highlighter`,
  `join`, `grouping`, `suggest`, `spatial3d`, `expressions` and
  `backward-codecs`.
* **968 declared divergences** from Lucene 10.5.0, each documented in the code
  where it occurs.
* **`BEST_COMPRESSION`** stored fields are byte-identical to Lucene's only with
  the `zlib-c` feature.
* **Thai segmentation** needs an installed JDK to match Lucene exactly.
* **Not on crates.io:** the crate name `rucene` is already taken there by
  another project, so `rucene` 0.1.0 cannot be published under that name.
